# HiFi Planner v2

Rebuild of HiFi Planner as a static web app. No build step and no dependencies: plain HTML, CSS and JavaScript that runs from GitHub Pages or by double-clicking `index.html`.

## Try it

- **Locally:** open `v2/index.html` in Chrome or Edge. Log in with a shop number.
- **Online demo:** push the `v2` folder to the `hifi-planner` repository. It is then served at `<your GitHub Pages address>/v2/` while the old planner stays untouched at the root.

## Admin

1. Settings (gear) → Admin → enter the admin code from `data/config.js` (`hifi-admin` until you change it).
2. **Product Editor** creates, edits, duplicates and deletes products and cables. **Save as Shortcut** stores the canvas or selection as a template.
3. Changes are drafts on that PC until **Publish**. Publish commits `data/own.js` (the master), `build/app-products.js` (so shops see the change at once, until the next hourly build regenerates it), `data/templates.js`, `data/site-ignore.js` and any uploaded images to the GitHub repository. Shops get them a few minutes later on reload. For products that follow the website, price, discount and colours are read-only in the Editor: they come from hifiklubben.dk every hour.
4. Publishing needs a GitHub fine-grained personal access token with *Contents: Read and write* on the `hifi-planner` repository only. Paste it under Settings → Admin. It is stored in that browser only.

The admin code only hides the admin tools; it is visible in the page source like the shop numbers. The GitHub token is what actually protects the data.

## Shop accounts and sellers

Login is two steps: the shop number, then the seller's own number (5–7 digits). Shop numbers on the list in `data/config.js` are known; a valid shop number that is not on the list can be created on the spot (*Butik … er ikke på listen endnu* → *Opret butik*, then the shop's details), and is then known on that PC. Anything else gets "Ukendt butiksnummer", as before. A created shop sends the event *Ny butik oprettet* (number and name) to the statistics, so a real one can be added to the list in `data/config.js`. The first time a shop is used on a PC, staff enter the shop's name, email and phone; the first time a seller number is used, its owner enters their name. Both are stored in that browser only. The A4 footer prints the shop's details and "Your adviser: <seller name>". The top bar shows the signed-in seller's initials; click them for a menu that starts with the shop's sellers on this PC (*Sælgere i Amagerbrogade*): click a name to switch to them at once (a toast says *Logget ind som …*; the signed-in seller is ticked), or *Anden sælger…* for the login screen (a seller number not on the list, or removing a seller from the PC). On tablets the same list is in ⋯. Only sellers who have logged in on this PC are listed: they are kept in this browser, not on a server. Switching from the menu never counts as having seen the statistics notice; that stays with the login screen. Sellers already used on the PC are listed for one-click login and can be removed there.

## Shortcuts

An admin saves the canvas (or the selection) as a Shortcut; Publish shares it with all shops. A Shortcut keeps everything on the canvas except the floor plan image: product cards (colour, front/back, left out of the price list), text boxes, marks with their letters, symbols, rooms, cable runs with their cable, the legend, the price list and the connections. It also keeps the drawing's settings: card size, CI mode, mark size, scale, A4 orientation and pages (`s` in the template).

- **On an empty canvas** (nothing drawn yet; a floor plan, legend or price list on its own does not count) the Shortcut goes back exactly where it was on the page, whether clicked or dragged in, and applies the settings. A scale already set for the floor plan is kept, and so is the orientation of a page that has a floor plan.
- **On a drawing in progress** the Shortcut only adds its items, at the drop point or in the middle, and the drawing keeps its own settings. A second legend or price list is not added.
- Shortcuts saved before this change (no `s`) contain only products, text, marks and connections, and no settings or page position: re-save them to get those. Copy/paste never changes settings and always pastes under the pointer.

## CI mode: marks on a floor plan

CI mode is for custom-install proposals. Upload a floor plan (JPG, PNG or PDF, or drop the file on the canvas); on landscape pages it leaves a column free on the right for the legend. A PDF is drawn to an image with the bundled pdf.js (`vendor/pdfjs`, Mozilla, Apache-2.0), which is loaded only when a PDF is opened; a PDF with several pages shows the pages so the seller can pick the floor plan. PDFs work in the online version, not when the planner is opened as a local file (browsers block it there).

**Dark theme:** the page stays dark like the rest of the canvas, and a floor plan is shown inverted on screen, with CI mode on or off (white paper becomes the page colour, black lines light grey; colours keep their hue). Printing, the PDF and the customer's page always use the original light plan.

- **Marks.** With CI mode on, clicking a product in the list arms it: every click on the canvas places one mark, Esc or right-click stops (dragging a product onto the plan places a single mark). Each product gets one letter (A, B, C…) and colour; the shape shows the kind of product: circle = ceiling speaker, square = wall speaker, triangle = subwoofer, hexagon = other/outdoor speaker, diamond = electronics. Marks have one size for the whole proposal (slider in the CI bar) and move on a 5 px grid.
- **Symbols.** The CI bar has generic symbols that are not products: rack, router, TV, listening position, volume control, cable outlet.
- **Legend.** Appears with the first mark and explains the plan: every mark with image, name and quantity, the symbols used, cable runs with metres, and the scale bar. It shows no prices. Movable; show/hide with the Legend button.
- **Replace.** "Replace all A" swaps the product behind every A mark and keeps the letter.
- **Cards and price list.** With CI mode off, products are added as normal cards (for a wiring diagram on another page). A card whose product has marks shows the same letter. The price list counts marks too; a product that is both marked and drawn as cards is counted once (the larger number). Any card or mark can be left out of the price list with the "In price list" button in the selection bar (or right-click → Count in price list); it stays on the drawing, marked "Not priced" on screen only. Stored as `np: 1` on the item.
- **Rooms.** "Room" in the CI bar: drag a rectangle around a room and type its name. The price list gets a "Per room (floor plan)" section with what each room gets and a subtotal: the marks in it and the product cards placed inside it (by the card's centre, so a card can be dropped into a room with CI mode off, e.g. a TV or an amplifier). Within a room a product that is both marked and drawn as a card counts once (the larger number), as in the price list. Marks outside every room are listed as "Outside the rooms"; cards outside are not (they are usually a wiring diagram on another page). Cables are not tied to a room. Move a room by the dotted grip beside its name, resize it at the bottom-right corner.
- **Scale.** "Scale": click the two ends of something with a known length (a wall, a door) and type the length in metres. The legend then shows a scale bar.
- **Cable runs.** "Cable": click along the route (points snap to the centre of marks), double-click or Enter to finish; the tool stays on for the next run. Each run shows its length once the scale is set. Select a run and choose "Cable" to pick speaker cable sold by the metre; the next runs get the same cable. Metres are summed per cable type, rounded up to whole metres; the legend shows the metres and the price list the cable. Runs cannot be reshaped afterwards: delete and redraw.
- **Data.** Rooms are `{ kind: 'zone', x, y, w, h, name }`, cable runs `{ kind: 'run', x, y, pts, cable }`, and `doc.sc` is the scale in canvas units per metre. Marks are items `{ kind: 'mark', k: <product id or '@symbol'> }`, the legend is `{ kind: 'legend' }`, `doc.mk` keeps the letter order and `doc.ms` the mark size (document version 3). Older CI drawings, where products were thumbnails, are converted to marks when opened.

## Grid and A4 pages

- The canvas grid is 20 units (100 when zoomed out). An A4 page is 1400 × 1000 units (portrait 1000 × 1400) and pages are 100 apart, so every page edge falls exactly on a grid dot. Printing scales the page uniformly to fit A4 and centres it (1.5 mm side margins, since 1400 : 1000 is 1 % narrower than A4).
- A new floor plan is placed on the grid and its frame is sized in whole grid steps; the image keeps its proportions inside the frame, so a measured scale stays true. Moving and resizing the plan keeps it on the grid.
- Drawings from before this change (document version 3, page width 1414, gap 60) are converted when opened: items on page 2 and later move with their page.
- **Each page landscape or portrait (2026-11-25).** Above each page, beside *A4 · liggende · 1/2*, a **Stående / Liggende** button turns that page. What is on it stays where it is on the page (moved in where it would stick out), the pages after it move along with everything on them, and Undo puts it back. A new page turns the way the last one does. Filer → *Alle sider stående/liggende* turns them all. Stored as `doc.po` (one orientation per page) only while the pages differ, else `doc.orient`; share links and QR codes carry it. Printing gives each sheet its own page size (CSS named pages), so one PDF can mix portrait and landscape; the **cover is always portrait**. `C.rotatePage`, `C.rotateAll`, `pageSize(i)`, `pageRect(i)` in `js/canvas.js`.

## Mouse controls

- **Soft zoom (2026-11-25):** the wheel, trackpad pinch and the zoom buttons ease to the new zoom in about a tenth of a second (each frame covers 35 % of what is left, so it never lags behind the wheel; the point under the pointer stays put). *Tilpas til vindue* (Shift+1) and zooming to an item from Oversigt glide there in 200 ms. Panning is always direct, and grabbing the canvas stops a glide. Off with the system's reduced-motion setting. `zoomSoft`, `viewTo` in `js/canvas.js`.

- Left-drag on empty canvas: selection box (Shift or Ctrl adds to the selection). A click on empty canvas deselects.
- Right-drag or middle-drag (also starting on a card): pan. Right-click without moving: the menu. Space + left-drag: pan. Scroll wheel: zoom.
- Left-drag on a card, note, mark or wire: move it. Whatever you move goes on top of everything else (the last moved is the topmost; the floor plan and rooms stay underneath); [ and ] still reorder by hand.

## Keyboard

- **Type to search.** A letter or number typed on the canvas goes into the product search in the sidebar and starts a new search, so the mouse can stay on the canvas. In the search box the first result is highlighted automatically, so a SKU + **Enter** adds that product at once; **↓/↑** move the highlight. Enter adds the highlighted result to the middle of the canvas, and the search and its results stay (Enter again adds another one; typing on the canvas starts a new search); **Shift+Enter** (or Enter with no search or no results) opens the Katalog with that search; **Esc** goes back to the canvas. Code: `keys()` in `js/main.js`, `Pn.typeSearch` and `searchKeys` in `js/panels.js`.
- **Shortcuts for the selection are Alt + a letter** (read by key position, so Option+letter works on a Mac): Alt+T text, Alt+B flip front/back, Alt+C variant, Alt+K Katalog, Alt+I inspect image, Alt+L lock the floor plan, Alt+R replace. Until 2026-11-21 they were plain letters, which now type into the search.
- **Shift+1** fits the drawing to the window (as in Figma and Miro). Unchanged: Delete, arrows (nudge), [ and ] (order), Enter (cable picker on a selected wire), **Alt+K** the Katalog (Enter on the canvas until 2026-11-23), Esc, Ctrl+Z/Y/C/V/D/A/P, F3, F4, /. Ctrl+S is Gem, Ctrl+Shift+S Gem som, Ctrl+O Åbn, Ctrl+Shift+L Del link (2026-11-25).

## Languages (since 2026-11-25)

Seven languages: **Dansk, English, Norsk (bokmål), Svenska, Nederlands, Deutsch, Suomi**. Choose under the seller's initials → *Sprog* (or ⋯ on a tablet); the page reloads in that language and the choice is remembered per browser. The first time, the browser's own language is used if it is one of these, else English.

- **What is translated:** the whole interface (menus, dialogs, the sidebar, the Katalog, the cards' labels, the price list and the A4 footer, the cover page, the guided tour, Help, the Produkt-editor and settings) and the category names. **The customer's page** opens in the seller's language when the link was made (`?l=sv` in the link; Danish links have none, so old links are unchanged).
- **What is not:** the catalogue itself (product names, the website's filter values such as product types) and prices come from hifiklubben.dk, so they stay Danish and in DKK; links go to hifiklubben.dk. The order-lines CSV for Business Central stays Danish. A shop in another country would need its own catalogue mirror (hifiklubben.no/.se/.nl/.de/.fi): not built.
- **How it works:** the code has English and Danish side by side, `t('English', 'Dansk')`. The other languages are dictionaries keyed by the English text, one file each in `js/i18n/` (`nb.js`, `sv.js`, `nl.js`, `de.js`, `fi.js`); `index.html` loads only the chosen one before the app starts. A key with `{}` is a template for text built with `+` (for example `"Delete {} from the catalogue?"`). Category names go through the same dictionaries by their English name. `HP.locale()` gives the date format for the language.
- **Adding or changing a text:** write it as `t('English', 'Dansk')` as always. Until it is added to the five dictionaries it shows in English in those languages (nothing breaks). Add it to each file with the English text as the key.

## Design language (since 2026-11-24)

The app's controls and windows follow the top bar's style, like Figma and Canva: 6 px rounded corners on controls (10–12 px on dialogs, menus and panels), light grey borders, a soft grey hover, an orange-tinted "on" state, an orange focus ring on fields, and dialogs, menus, the Oversigt panel and the Katalog floating on soft shadows instead of black frames. Labels and headings are in sentence case in the UI font (Segoe UI). Monospace is kept for SKUs, keyboard keys, counts and figures, and Sharp Grotesk for product names. **Not changed on purpose:** the cards, wires and price list on the canvas, the A4 pages, the cover and the customer's page keep the sharp HiFi Klubben look, because they are what the customer sees and prints.

The shared settings are CSS variables in the "v5 design language" sections at the end of `css/app.css`: `--r` (6 px), `--r-sm`, `--r-lg`, `--r-xl`, `--ctl` (control height, 32 px; 38 px on touch screens), `--tint` (the "on" state), `--ring` (focus), `--line2` (hover border) and `--pop` (the floating shadow, darker in the dark theme).

**Icons** are [Lucide](https://lucide.dev) (ISC licence: free for commercial use, the notice is in `assets/LICENSE-lucide.txt` and must stay with them). They are copied into `ICONS` in `js/core.js` (no download at run time), each with its Lucide name after `//`; to add one, find it on lucide.dev and paste the inside of its `<svg>`. Drawn at 1.75 stroke with round ends (`.ic` in `css/app.css`). The HiFi Klubben logo, the CI mark symbols and the port dots are our own, not icons.

**Product rows** in the sidebar, the cable picker and the systems list have two lines with the price in its own column on the right, so it is never cut off: *name …… price* (red on sale, *fra* when variants differ, */ m* per metre) above *brand · size +3 ⓑ ⓦ …… −48%*. A discount of 10 % or more shows as the −% tag (the old price on hover); a smaller one as the old price, struck. On a narrow sidebar the brand is cut with … before anything else (`rowInfo` in `js/panels.js`).

**Dropdowns** (`<select>`: Alle sektioner, sorting, the Katalog's sort, the cable picker, the Editor's port fields) open a list in the same style as the ▾ menus: rounded, soft shadow, grey hover, the chosen one bold with an orange ✓, the arrow turning up while open, and a long choice cut with … in the closed field. This uses the browser's customizable select (`appearance: base-select`, Chrome and Edge 135+); `js/core.js` adds the `<button><selectedcontent>` each select needs, also after its options are rebuilt. Other browsers (Safari, Firefox) show their own list; the closed field looks the same. Keyboard, type-to-find and touch work as with any select.

**Scrollbars** are thin, rounded and float on a clear track (12 px, the thumb 4 px wide; darker and wider on hover, orange while dragged), in Chrome, Edge and Safari; Firefox gets its own thin scrollbar in the same colours. Colours: `--sb` and `--sb-hover`. Open dropdown lists get the same scrollbar (`::picker(select)::-webkit-scrollbar`). Strips that hide their scrollbar (category chips, the selection bar and CI bar on small screens) still do.

## Motion

Short and snappy (100–180 ms), in the "v4.5" CSS section; all of it is switched off when the system asks for reduced motion (`HP.reducedMotion()`).

- **Dragging:** cards follow the pointer exactly while dragged (with a slightly deeper shadow) and settle onto the grid with a 110 ms ease on release, the wires following frame by frame; one step for Undo (`startItemDrag` in `js/canvas.js`).
- **New cards** fade and rise in when up to 12 appear at once (added, pasted, a system); opening a whole drawing does not animate.
- **Search results** slide in with a slight stagger when the search changes; the highlighted result moves smoothly.
- **Dialogs, the Katalog, the right-click menu, toasts and the selection bar** fade and scale in; the Katalog fades out when closed and its tiles fade in.

## Phones and tablets

The app works on phones and iPads with touch.

- **Layout.** Up to 1024 px wide (iPad portrait, phones) the product list is a drawer opened with the orange **Products** button, and a **⋯** button holds everything that does not fit in the top bar. Up to 700 px (phones) the top bar only keeps Products, undo, the proposal's name, Print and ⋯; windows open full screen.
- **Canvas gestures.** One finger on empty canvas pans; two fingers pinch-zoom and pan. Long-press (about half a second) opens the context menu on a product, cable or empty spot; long-press on empty canvas and then drag selects an area. Dragging items, wiring (tap an output dot, then an input dot) and the CI tools work with a finger; drawing a cable run has a **Finish run** button.
- **Product list.** Scrolls with a finger. Tap adds the product (in CI mode: arms it for placing marks); long-press picks it up for dragging onto the canvas, and the drawer slides away while dragging.
- **Touch details.** Larger hit areas for port dots and resize handles; form fields use 16 px text so iOS does not zoom when typing; the full-screen image viewer supports pinch and double-tap. Code: `drag()` and the pinch handler in `js/canvas.js`, `listDrag()`, `Pn.drawer` and `moreMenu()` in `js/panels.js`, the "v3.0" section of `css/app.css`.

## Prices you can rely on (2026-11-25)

Found on Hisense M2: HiFi Planner showed 6.999,- (with a before-price of 10.999,-) for hours after the website's campaign had ended, under the product number HISM2 where the till and the website say HISM2PRO. A wrong campaign price is a promise the shop has to keep. What was wrong, and what guards against it now, layer by layer:

1. **The hourly sync did not run hourly.** GitHub runs scheduled workflows only when it has capacity: on 24–25 November the hourly schedule fired 3 times in 20 hours (23:3x, 08:48, 19:24 UTC), so the prices from 08:48 stayed until 19:24. The workflow now **starts its own next run** about an hour after each run started (a `workflow_dispatch`, which GitHub always runs; the newest run carries the chain, so there is only one), with the schedule (now twice an hour) as a backstop that restarts it. A failed push is retried 5 times instead of losing the run. `tools/price-sync.workflow.yml` → copy to `.github/workflows/price-sync.yml`.
2. **Open tabs kept the prices they were opened with.** A shop's tab open since the morning showed the morning's prices all day. The build now writes `build/stamp.json` (`pricesAt`: when the website's prices were read, from the mirror's listing) and puts `pricesAt` in `build/app-products.js`. Every open tab checks the stamp every 5 minutes, when it comes back into view, and right before printing, and loads a newer catalogue in place (the drawing stays): *Priserne er opdateret fra hifiklubben.dk*. `HP.checkCatalogue` in `js/core.js`.
3. **Old prices never show a campaign.** When the loaded prices are more than **3 hours** old (`HP.STALE_HOURS`), every price with a before-price shows the before-price, without a discount: cards, product list, Katalog, systems, price list, cover and customer page. A seller can then only under-promise (the till gives the customer the lower price anyway). The top bar shows an orange chip *Priser 11 timer gamle* (click: what it means, *Tjek igen*, and for admins *Hent priserne nu*), the price list says so on screen, and the print dialog warns. The campaign prices are only set aside in memory (`_sale`), so nothing is ever saved or published without them. `guardPrices` in `js/core.js`.
4. **The printout says when the prices were read**, not today's date: *Priser fra hifiklubben.dk pr. 25.11.2026, 20.26*, plus *Kampagnepriser er ikke vist* when they are off. The same on the customer's page.
5. **The till's SKU.** A card that is one sellable item now carries the variant's SKU (HISM2PRO, the till's and the website's *varenummer*), not the website's product number (HISM2, kept as `site`; searching for it still finds the product). 585 cards changed. Cards with colours still give the chosen colour's SKU (`C.skuOf`).
6. **Edited products never bring old prices back.** An admin's draft is a copy from the day it was edited. A product whose price comes from the website is now marked `live: 1` by the build; for those, the price, discount, variants and SKU always come from the newest catalogue, both in the admin's own browser and when Publish writes `build/app-products.js` (which used to write the draft's old price for every shop until the next build).
7. **No price is never 0,-.** A product without a price (discontinued, not linked) shows *Ingen pris* in the price list and Oversigt (*Pris oplyses i butikken* on the cover) and is left out of the total, with a note to check the till. A price set by hand in Prisjusteringer counts as usual.

Still true: prices are not live. The till is always right; HiFi Planner now errs on the side of the higher price, and says how old its prices are.

## Catalogue sync (hifiklubben.dk mirror)

A GitHub Action runs every hour, starting its own next run (see *Prices you can rely on*) (`tools/price-sync.workflow.yml`; copy it into the repository as `.github/workflows/price-sync.yml` once). It can also be started under Actions → Catalogue sync → Run workflow, or from Settings → Admin (token needs *Actions: Read and write*). Each run's report is under Actions → the run → Summary.

What it keeps in step with the website:

- **Prices and discounts.** The website's `priceBefore` is stored as `was`; the price list shows the old price struck through, "Save X%" and the total saving. Since 2026-11-25 a price is only ever held **upwards**: a price that rose (a campaign ended) is taken at once; a price that fell more than 35 %, or one whose SKU several catalogue products use, keeps the old, higher price **without a discount** and is listed under *Held prices* in the report for a human to check. (Before, rises of more than 60 % were held too, which kept ended campaign prices.)
- **Variants.** Products sold in several colours or finishes get `vars` (name, price, discount, image). A card always has one: the one searched for or picked in the Katalog, else the website's default (the variant whose SKU is the product's own), else the first (`C.variantFor`; also after Udskift). How a card shows them depends on what they are (`C.varStyle`): **colours** that all look different get a dot each on the card image (one click to switch); anything else, such as **TV sizes, amplifier models, cable lengths** or colours that look alike, gets a **pill** with the chosen one's name and how many there are (*55" · 5 ▾*), and a click lists them all with their prices. The sidebar shows such variants as text (*48" +4*) and the Katalog tiles as named buttons instead of pictures. The website's data does not say what kind a variant is, so it is worked out: a variant name with a digit in it, or all variants one colour, means not colours. Staff change it on the card, with the *Variant* button, right-click → *Variant…*, or Alt+C. The card image, card label and price list follow the choice.
- **Discontinued products.** A product the website no longer sells new gets `gone: <date>` (the date it was first seen gone, kept from build to build): an UDGÅET tag on the card (not printed). That includes a product of which the website only has **outlet units** left (demo/exhibition pieces at a reduced price, "Kun Outlet"; `goneWhy: 'outlet'`, the tag's tooltip says so): outlet units are never used as prices or products. A product linked to the website clears itself when the website sells it new again. Products frozen at the switch (not linked to a website product) are gone as soon as their SKU is not sold new; our stand-ins and products without a SKU never are; a frozen product the website does sell is left as it is and listed in the report for linking in the Editor (`tools/catalog-build.js`; the report's *Only outlet units on the website* and *Not linked, but the website sells them*). Until 2026-11-23 a product with only outlet units kept its status, and frozen products never became gone (23 such products were shown as current, e.g. Classic HDMI 10m, B&W 803 D4, NAD C658).
- **Every product has a SKU** (since 2026-11-23): the SKU is what ties HiFi Planner to HiFi Klubben's other systems (order lines, stock, Business Central), so a product without one is discontinued (`goneWhy: 'nosku'`, tooltip *Intet varenummer*). A product linked to the website without a SKU of its own gets the website's from the build (the variant SKU for a one-variant card such as a cable length, else the product SKU; listed in the report under *SKU taken from the website*: saving it in the Editor keeps it in `data/own.js`). Only our stand-ins (Tilbehør > Pladsholdere: generic TV, amplifier…, not products for sale) have none. The Editor does not save a product without a SKU (it is upper-cased). Products discontinued for this on 2026-11-23: Basic Minijack1 0.5/1/2 m (the old Argon Audio cable, now Essentials, no longer sold), Fender x MoFi Precisiondeck, Sinox SXA 1800. The Sonos Line-In Adapter came from the old planner without a SKU and was matched to the website by name, which set its link but not its SKU: it is SONLINEINADAPT.
- **Gone products are not offered:** the sidebar search, the replace dialog, the cable pickers and the Katalog leave them out, unless the search is the product's exact SKU (product, colour or length SKU; `cat.findable`, `cat.skuWord` in `js/core.js`). Cards already on a drawing keep their UDGÅET tag. The report suggests likely successors.
- **New products.** Website products of a relevant type (amplifiers, speakers, TVs, sources, cables…) are added automatically, marked `review` with an AUTO tag on the card. Their inputs/outputs are suggested from the website's connection specs. In the Editor, the **Review** tab lists them; the website panel shows the product's image gallery (pick the front and back-panel image), the listed connections and a "Use suggested ports" button. Saving a product marks it as checked. Deleting an auto-added product puts its SKU on the ignore list so it is not added again. Everything else on the website (mostly accessories) is under the **Website** tab.
- **Bluetooth/WiFi.** Switched on when the product page lists it. The sync never switches them off, because the website's lists are sometimes incomplete; ticking them by hand in the Editor stops the sync from touching them.
- **Images.** Website images are referenced as `hk:<image id>`. `tools/mirror_images.py` copies them into `img/hk/` (640 px) and `img/hd/hk/` (1600 px, front/back only), up to 400 per run. Until a copy exists, the app shows the image straight from images.hifiklubben.com: the card size (`pdp_d`), and if that fails or has not come in 4 seconds, the small size the product list uses (`pcs`, usually already in the browser's cache). images.hifiklubben.com sometimes leaves requests for the larger sizes hanging without an error (seen 2026-11-23), which left cards blank (`S.fallback`, `S.onerr` in `js/site.js`).

Product pages are read in batches (60 per run, new products first), so all pages are refreshed about once a day. `tools/sync-report-2026-11-15.md` is the first full run against live data.

**Load on hifiklubben.dk.** Each run reads the website once: the listing (~28 requests of 50 products) and 60 product pages, one at a time with a pause between them, about 90 requests an hour, identified by its User-Agent (*HiFi Planner catalogue mirror*). That step is `tools/mirror.js`, the first step of the workflow; `tools/price-sync.js` runs after it with `--mirror` and reads the listing and the page details from `mirror/` instead of the website (until 2026-11-20 both read the website, about 175 requests an hour). The mirror keeps, per page, what price-sync takes from it (`hp`: spec table, the description's connection lines, gallery, availability, parsed with the same `S.parsePage`). Prices stay hourly: if the mirror step fails, price-sync reads the listing from the website itself (its listing must be under 2 hours old, `listingAt` in `mirror/index.json`); product-page details then wait for the next run. Images come from images.hifiklubben.com, each only once.

**Website mirror.** First in each run, `tools/mirror.js` updates `mirror/`: the raw listing, the product record of about 60 product pages per hour, an index of every website SKU (first/last seen, gone) and `types.json`, which compares the website's product types with what HiFi Planner maps. The run summary lists new website types and the types the sync does not map, so a missing category (like projectors) shows up there instead of being skipped silently. The mirror step may fail without stopping prices and images from being committed.

**Normalized catalogue (stage 2).** `tools/catalog-build.js` turns the mirror into `build/catalog.json` and `build/report.md`, every hour after the mirror:

- **Categories** are the website's own tree (from the product pages' breadcrumbs, identified by URL path such as `/tv/projektor/`), plus a few of HiFi Planner's own (Væghøjtaler, Pladespillere, Moduler & opgraderinger).
- **Rules** live in `tools/taxonomy.js`, the only hand-edited part: for every website type key (`modelTypeKey`, e.g. `InCeilingLoudspeaker`) its *kind*, *scope* (`diagram` = drawn and wired, `pricelist` = on proposals without ports, `skip`), *facets* (active, wireless, battery, mount, role, cable connector) and, where the website files it oddly, the category to move it to. A new website type without a rule is listed in the report.
- **Products** carry variants (SKU, colour, EAN, price, stock, image), the variant kind (colour, size, metre), flattened specs, and the website's accessory/alternative SKU lists. **Bundles** become parts lists (product SKUs with quantities).
- **report.md** compares the result with today's catalogue: where today's categories end up, Bluetooth/WiFi/per-metre differences, products not on the website, and what is new per category.

**Own layer (stage 3).** `data/own.js` holds only what HiFi Planner adds, one entry per catalogue product: the id (what saved drawings and Shortcuts refer to), brand/name/SKU as HiFi Planner shows them, picked images, ports, cable connectors, today's categories (legacy), Bluetooth/WiFi, review status, and a `link` to the website product it follows (`site` = product SKU, `v` = variant SKU when the card is one variant such as a cable length, `single` = the card is one speaker of a pair the website sells as a pair). Products the website does not list keep their last website facts in `frozen`.

- Until the switch, `tools/own-split.js` wrote `data/own.js` from `data/products.js` every hour, and `tools/catalog-build.js` rebuilds `build/products.js` from the own layer and the mirror, using the sync's own matching and price logic (`tools/site-match.js`, copied unchanged from `price-sync.js`), including its plausibility check (a price that jumps more than −35 %/+60 % is held and listed).
- The **round trip** section of `build/report.md` compares the result with `data/products.js` field by field. First run: 847 of 847 products identical.

**The app catalogue (stage 4, live since 2026-11-19).** `index.html` loads `build/app-products.js` and `build/categories.js` (it loaded `data/products.js` before; rollback: put that file back in the loader in `index.html`). Every product there carries its website category path in `cats` (e.g. `['/tv/', '/tv/projektor/']`; today's categories are kept in `lcats`), plus `kind`, `scope` and the website facts in `fx` (mount, active, wireless, per metre…). Products the website does not list get the category most of their old category's products went to (stand-ins: Tilbehør > Pladsholdere). The website products HiFi Planner does not have yet are added (`web: 1`, id `w-<sku>`, no ports). `build/categories.js` holds the category tree (`HP_DATA.categories`, section order and English names in `tools/taxonomy.js`).

- The sidebar groups by the website's sections (Højtaler, HiFi, Surround, TV, Pladespiller, Høretelefoner, Kabler, Tilbehør) and their categories; search also finds category names (`projektor`).
- CI marks take their shape from the website type (ceiling, in-wall, on-wall, subwoofer), and the cable-run picker also offers the cables the website sells by the metre.
- **The Editor** saves to `data/own.js` through Publish (`HP.toOwn` in `js/core.js` turns a product into its own-layer entry; the link to the website product is kept). The category is picked from the website's tree; a category chosen by hand is stored as `cat` and wins over the website's (`wc` holds the website's, shown in the Editor). Website products HiFi Planner does not have yet are in the catalogue as `w-<sku>`: diagram gear is listed under **Review** until someone adds its ports and saves it, which adopts it into `data/own.js`. Deleting one puts its SKU on the ignore list.
- **The hourly run** no longer writes `data/products.js`: `price-sync.js` still reads the website for its report, the product-page details (`data/site-details.js`) and the Website tab (`data/site-new.js`), and `own-split.js` does nothing (both check whether `index.html` loads `build/app-products.js`). `catalog-build.js` rebuilds `build/app-products.js` from `data/own.js` and the mirror; the plausibility check now compares with the previous build, and the report lists the changes since the previous build.
- **Corrections of website facts** live in `tools/overrides.js`, per website product SKU (kind, scope, facts such as `perMetre`, category, with a note), applied by the build and listed in the report. Example: the SLiP cables, which the website sells by the metre but marks as colours.
- **Stock pictures**: a local image file used by cards of 3 or more different website products (the generic RCA photo that was on 23 speaker cables) is replaced in the build by each product's own website photo.
- Still to do: ports for the new website products, banana/spade/bare-wire speaker connectors, and using the facets in more places (filters).

## Katalog (full-screen product browser)

A large dialog over the canvas (the drawing stays visible, dimmed, behind it; a click outside closes it), laid out like hifiklubben.dk so staff know where things are, drawn in HiFi Planner's own style, light and dark (`js/katalog.js`, the "v4.3" CSS section). Product photos keep a light background in dark mode, as they are shot on white.

- **Open:** **Alt+K** (until 2026-11-23: Enter on the canvas), Shift+Enter in the sidebar search (that search, across all sections, like the website's search page), or the Katalog button. **Esc** clears the selection, then closes (wherever the keyboard focus is). Filters are kept while the page is open, so the seller can go back and forth with a customer.
- **Top:** title, search, sort, close. **Menu:** the website's sections in its order (HI-FI, HØJTALER, PLADESPILLER, HØRETELEFONER, SURROUND, TV, SYSTEMER, KABLER, TILBEHØR) with counts, and TILBUD in red (only discounted products, in any section). Under a section its categories as round pictures (each the category's first product picture).
- **Left column**, collapsible groups as on the website, each option with the number it would give: **Type** (the website's product type, `ty` on the product, written by `tools/catalog-build.js`, e.g. *Gulvhøjtaler – Aktive*, *Passiv subwoofer*; products the website does not list use their category), **Pris** (from/to), **Vis kun** (Tilbud, Bluetooth, WiFi), **Tilslutninger** (from the ports: phono input, HDMI ARC/eARC, HDMI/optical/coaxial/analogue input, USB-DAC, XLR, sub out, pre-out, speaker and headphone outputs) and **Mærke** (top 10, "Vis alle"). The active filters show as pills above the grid ("Nulstil" clears them). On narrow screens the column opens with **Filtre**.
- **Tiles** as on the website: picture on grey, SPAR x % (systems: SPAR x kr. against the parts one by one), colour pictures (click one to pick that colour, before or after selecting the tile; the colour is kept while the page is open), name, type, price in red with FØR when discounted. Discontinued products are not shown (unless searched by their exact SKU).
- **Cables** (since 2026-11-23) are in the Katalog as in the sidebar: one tile per cable (`cat.cableGroup`), named without a length, with its lengths as buttons (four around the chosen one; **+N** lists them all with prices). The length shown is the one searched for, else the one used last; picking one changes the tile's picture, price and what is added. Cable sold by the metre shows its price per metre and is added with the metres last used (− N m + on the card). Price filter and price sorting use a cable's cheapest length.
- **"Ingen porte endnu"** is shown to admins only, on website products that are drawn and wired (scope `diagram`) but have no ports yet, not on wireless headphones; accessories and cables have none and need none (until 2026-11-23 it was on every website product, 466 tiles).
- **Adding:** click a tile (or its Vælg box) to select it; the bar at the bottom shows how many and the total, and **Tilføj til lærredet** (or Enter) adds them side by side in the middle of the view, five to a row, as one step for Undo (`C.addProducts` in `js/canvas.js`). A double-click adds one tile at once. **Quantity:** a selected tile shows **− 1 stk. +** beside *Vælg* (type a number too, 1–99; − at 1 deselects; + and − on a focused tile); each piece becomes its own card, side by side, and the bar counts pieces (*5 stk. af 2 produkter · 183.995,-*, *Tilføj 5 til lærredet*). Changing a tile's colour or length keeps its quantity. Systems are added wired, as from the sidebar.

## Systems (the website's bundles)

hifiklubben.dk sells ready-made systems (bundles): a turntable with an amplifier and speakers, a receiver with a 5.1 speaker set, a soundbar with a sub. The sidebar lists them under the **Systemer** chip, after the categories, with the website's own types as sub-chips (Stereosystem til TV, Soundbar system/pakke, Pladespiller system…), the Sale chip, the brand filter and sort order. The search box finds systems by name, type, or any part's name, brand or SKU; while searching under another chip, the Systemer chip shows how many systems match. Each row shows the bundle price, what it saves against the parts one by one, and the parts.

- **Dropping a system** (drag, or click/tap) places one card per part, in columns from the sources to the speakers (turntable → amplifier → speakers; a receiver's speakers in the order of its outputs, so the wires do not cross), and wires them. The wires have no cable: the seller picks the cables. Parts that are not wired (stands, a backbox) go in a row underneath. The whole drop is one step for Undo.
- **Wiring** is worked out by `P.autoWire` in `js/ports.js` from the cards' ports, so ports corrected in the Editor are used at once. The best matches are taken first: same signal, then the same group (line/aux/pre…, HDMI, USB, coaxial); a sub output only feeds a subwoofer and is preferred over a line or pre output; FRONT/CENTER/SURROUND outputs go to the matching speakers (the dearest pair in front); a dedicated box such as a phono stage is used before the amplifier's own input; an input named for the source (LINE IN CD for a CD player, TUNER, NETWORK, TV) and the same plug at both ends win ties; numbered ports are used from 1. Each input takes one wire, each output gives one, and two cards are joined once, except that a stereo amplifier's L and R outputs both go to a speaker pair card, and a stereo output without L/R feeds two single speakers (e.g. Phantom K-60 (1 Unit) ×2).
- **Not wired:** wireless systems (Sonos, Bluesound Pulse, Marshall, Ambeo, KEF's wireless sub kit) and speaker sets without an amplifier are placed as cards. A part without ports yet (a website product not reviewed in the Editor) is placed but cannot be wired; once its ports are added it is wired on the next drop. The toast after a drop says how many cards and connections were made and how many parts were left without a wire.
- **Price list:** every complete set of a system's cards is one line, *System* + the bundle's name and link, at the bundle price, with its parts listed underneath and "Spar X%" against the parts one by one (or the website's own before-price, if higher); the saving counts in "Du sparer". Each card shows a small SYSTEM tag (not printed). If a part is deleted, the remaining cards are priced one by one; duplicating a whole system prices it twice. Cards carry the bundle's SKU as `sy`, which Shortcuts, copy/paste and share links keep.
- **Data:** `build/bundles.js` (`HP_DATA.bundles`), written every hour by `tools/catalog-build.js`: the website's bundles whose parts are all in the app catalogue (220 of 253 on 2026-11-21), each with its parts as app product ids and quantities, the colour when the bundle comes in one, the bundle price and before-price. The report lists the bundles left out and why. Of the 194 with two or more drawn parts, 121 wire completely, 5 partly (a wireless part) and 68 not at all (wireless systems and speaker-only sets).

## Related products: cables and accessories

**Relaterede produkter** in the top bar (an accent button whose label stays visible on narrow screens; the number counts connections without a cable), the notice under the price list ("3 forbindelser uden kabel · Relaterede produkter →", on screen only), or "Relaterede produkter…" in the right-click menu (of a card: for that product only) opens one dialog (`js/complete.js`):

- **Connections without a cable**, each with a suggested cable (speaker wires between the same two cards, such as SPEAKER OUT L and R to one speaker pair, are asked about once: the cable goes on one of them, since some speaker cables are sold as a pair and some singly) that fits both plugs and a length: a cable hifiklubben.dk lists as an accessory of one of the two products (★) first, then the cable last used for the same pair of plugs (remembered per browser), then the cheapest. Speaker cable sold by the metre gets 3 m, other cables the shortest length of at least 1 m. Cable and length can be changed per row; all rows are ticked.
- **Accessories**: hifiklubben.dk's own accessories for the products on the canvas, grouped per product, without what is already on the canvas and without plain cables (those are chosen per connection). Adapters are offered as accessories as well as on connections (Essentials Wireless Connect, Wireless Audio Adapter, Sonos Line-In Adapter; not Y-splitters); `facets: { accessory: true }` in `tools/overrides.js` does the same for any other product. Only shown, nothing saved or sent back. The print dialog has "Vis relaterede produkter på kundens side" (on by default, remembered; stored as `cv.r`, `0` = off, in the link).
- **The customer's page** is written for the customer, always in Danish: "Hej <customer>!" with a short thank-you from the shop signed by the adviser, **Ring til <first name>** / **Skriv en mail** buttons (`tel:` / `mailto:` from the shop's phone and email, the mail's subject is the proposal's name), the proposal with a small picture on each line and the date written out (23. november 2026), the drawing under "Sådan hænger det sammen", the related products under "Måske har du også brug for", and the adviser's details with the same buttons at the bottom. The printed cover is unchanged.
- **The QR code is always there (2026-11-25).** The whole proposal travels inside the link, so a big proposal (many cards, marks, notes) used to make a code too dense to print, and the cover said *Bed din rådgiver om et link* instead. Now the link in the QR code is written compactly (format `Q`: short product ids, `~` + a 6-character hash that the customer's page turns back with the catalogue, and the data in base 43, the characters a QR code stores in 5.5 bits instead of 8; tested with a QR reader) and the cover tries in turn: the whole proposal with error correction M (up to version 25), then with L (up to 30), then **products and prices only** (`HP.share.lite`: cards, marks, cables and adapters on connections, cable runs; no positions, notes or rooms) with M, then L up to version 40. A first step toward creating a sales quote in Business Central from a proposal; the next step needs HQ's item numbers and an integration.

## Adapters in a chain (Y-splitters) and cables from the product search

- **Adapters:** a cable product with a female and a male end (Y-splitters such as *Classic Y-Split 2M 1F*, *Y-Splitter (1F/2M)*, extenders; `P.isAdapter`, from the plug data in `build/app-products.js`) can sit between a cable and the in port. The cable picker shows **Med adapter** when one fits the in port and some cable can reach its socket; picking one matches the cables to the adapter's socket instead. Example: Forte A5 MK2 SUB OUT (1× RCA F) → Basic Sub 3 m → Classic Y-Split 2M 1F → Malmö Sub 10 LINE IN (2× RCA F). Stored on the connection as `ad`; the wire label reads *Basic Sub 3m + Classic Y-Split 2M 1F*, the price list counts both, share links and Shortcuts keep it (`P.chainIssues` checks both links of the chain for plug warnings).
- **Cables in the product search:** the sidebar search lists every product, cables and adapters included. Drag a cable onto a wire (the wire lights up) and it goes on that connection (cable sold by the metre: the last length used, else 3 m); an adapter goes in the chain. With a connection selected, clicking or pressing Enter on a cable in the list does the same. A cable card already on the canvas can be dragged onto a wire too: the cable goes on the connection and the card goes away (Undo brings it back). The drop finds a wire within about 10 px of the pointer, or its label, also in CI mode. Dropped anywhere else, a cable is a card as before (`C.setConnCable`, `C.dropProduct`, `wireAt` in `js/canvas.js`).
- **A cable's lengths are one product** (since 2026-11-23): whether the website sells a cable as one card per length (*Black Lab - Sub 2m … 20m*), as one product with lengths (*CL1 HDMI 8K*, 1–10 m, `lens`), or by the metre (*Rocket 22*, *SLiP*), the planner treats it the same way, like a product with variants. `cat.cableGroup(p)` in `js/core.js` gathers the cable's cards (one website product, or one family of length cards: same website SKU, else brand + name without the length) and its lengths, the same list the cable picker shows for a wire.
  - **Search:** one row per cable: the name without a length, *fra* the cheapest length (or the price per metre), and the length that will be added (*5 m +4*, *pr. meter*). ## Price adjustments (custom price proposals)

Prices and discounts for one proposal, without touching the catalogue: **Filer → Prisjusteringer…**, **Priser** in the price list's header, right-click the price list → **Rediger priser…**, right-click a card → **Ændr pris…**, or a price in Oversigt. The dialog has Business Central's POS discount actions (in HiFi Planner's own button style) over the price list's lines:

- **Ændr pris** (Change Price): the selected line's unit price (empty: the website's).
- **Linjerabatbeløb** (Line Discount Amount): the selected line's discount, in kr or in % (of its unit price).
- **Total rabatbeløb** (Total Disc Amount) / **Total rabat %** (Total Discount %): spread over the lines, as in Business Central's POS: kroner in proportion to the lines' amounts (whole kroner, the remainder on the largest line), a percentage as that percentage of each line (rounded per line). It replaces the lines' discounts.
- **Nulstil rabatter** (Reset Discounts): everything back to the website's prices (asks first; Undo brings it back). ↺ on a line resets that line.

**Every field responds to the others** (since 2026-11-24): the line discounts are what is stored; *Ekstra rabat* (kr and %) is always their sum, so a discount on one line updates the totals at once, and a total updates every line. Click a line, then an action, or type straight into a field (Enter moves to the next line). Every change is one step for Undo.

**The website's discounts** count as a campaign discount on top of the normal price (its FØR price): each line shows its normal price with *kampagne −38 %*, and its amount with the customer's discount all in (*−44,3 %*); the totals read *Normalpris i alt → Kampagnerabat (hifiklubben.dk) → Prisændringer → Ekstra rabat → Total*, and *Kunden sparer* in kr and % of the normal price. **også kampagnevarer** (remembered per browser, on by default) decides whether a total discount is spread over lines already on campaign too, or only over full-price lines; switching it spreads the last total again (kr stays kr, % stays %). Totals set before 2026-11-24 (`ta`/`tp`) are turned into line discounts when the dialog is opened.

- **Always visible to the seller, never to the customer** (since 2026-11-24): the chip in the top bar; a band under the price list's header (*Prisjusteringer · −3.000,- · Rediger · Ryd*) and a *TILPASSET* tag on each line with a price adjustment; a *PRIS ÆNDRET* tag on the cards counted on such a line (tooltip: the price and discount); a note in the print dialog (*Tilbuddet har prisjusteringer: −3.000,- i alt · Rediger*). ## I/O standard: ports, connectors and cables

Every port is `{ key, label, sig, conn }`:

- **label**: what is written on the product, free text in the Editor (`AUX IN`, `CD`, `TAPE IN`, `Line In (Analog)`). Older ports were named `SIGNAL DIR DETAIL` (`HDMI IN 1`, `SUB OUT 2`), which still works.
- **sig**: what the port carries, from the list in `js/ports.js` (`SIGNALS`: line, aux, phono, coax, sub, speaker, hdmi-arc, usb…). For a new port the Editor suggests it from the label (AUX/LINE/CD/TAPE → line or aux, MM/MC/PHONO → phono, USB-C → usbc) until one is picked by hand.
- **conn**: the physical connector, from one strict list (`CONNECTORS`): RCA, XLR, Jack 6.35 mm, Minijack 3.5 mm, Jack 4.4 mm, Jack 2.5 mm, XLR 4-pin, DIN, Speaker terminal, Speakon, Toslink, Mini-Toslink, BNC, HDMI, USB-A, USB-B, USB-C, Micro-USB, RJ45, RS-232, Antenna, Power (IEC), Wireless, Other. Speaker terminals are one type (no banana/spade/bare wire yet). Older values are mapped wherever they appear (`P.conn`): `coax` and `sub` → RCA, `trigger` → Minijack, `usb` → USB-A/B/C from the label and side; `tools/migrate-connectors.js` converted the ports in `data/own.js` (501 ports on 202 products, report in `build/connector-migration.md`; it runs every hour and does nothing once everything is converted).
- **key** is made from the label once and then kept, also when the label is edited later, so wires in saved drawings stay connected.
- Wires and port dots are coloured by the signal where one plug serves several uses (RCA: line, coax, sub; `P.colorOf`), otherwise by the connector.

**Cables** have two ends, `ends: [A, B]` (connector ids). The cable picker offers a cable as *matching* when its two ends fit the two ports, either way round (`P.cableFit`): a Minijack ↔ RCA cable for a minijack output to an RCA input, but not for RCA to RCA. In the Editor a cable has *End A* and *End B*. Ends set there are stored in `data/own.js`; for all other cables `tools/catalog-build.js` works them out (`tools/cable-ends.js`, marked `endsAuto`): from the connectors named in the cable's name, in order (`Evergreen - Minijack - RCA`, `USB B - USB A`, `USB CC`), else the website's connector list (`Stik`), else the usual plugs of the cable type (HDMI cable → HDMI ↔ HDMI, subwoofer cable → RCA ↔ RCA). The report lists the guessed ones (a USB cable that does not say which USB, Y-splitters) for checking in the Editor. The website itself has no standard for this: only 35 of 154 cable pages list connectors, and never which end is which.

**Cable lengths.** In the cable picker each cable is one row, with a button per length and its price; the cards of one website cable (one per length, e.g. *Evergreen - Minijack - RCA 1m … 16m*) and the website's own lengths (`lens` on the product, from the variants' *Kabellængde*, added by `tools/catalog-build.js`) are shown together. Clicking a length only selects it, so lengths and cables can be compared: the bar above the buttons shows the choice with its price (*Evergreen - Minijack - RCA 3 m · 999,-*), and **Brug kabel** puts it on the connection (Enter or a double-click does the same; Annuller leaves the wire as it was). Clicking the row selects the wire's current length, else the length used last, else the first of at least 1 m. A length that has its own card in HiFi Planner picks that card; any other website length is stored on the wire as `lv` (its SKU) with the website's price. Cable sold by the metre (speaker cable such as Rocket or SLiP) gets a metres field in whole metres instead, as cable is cut in the shop (Enter commits), stored as `m`, and is counted per started metre in the price list, like CI cable runs. The wire's label and the price list show the length (*Evergreen - Minijack - RCA 20 m*, *Rocket 11 3,5 m*). Share links and Shortcuts keep `lv` and `m`.

**A length the website stops selling.** A card for one length of a cable (e.g. *Rocket 44 Single-Wire - 1.5m*, AQROCKET44SC1,5AA) is not marked discontinued when only that length leaves the website: `tools/catalog-build.js` finds the cable by the SKU with the length taken out (AQROCKET44SC#AA → AQROCKET44SCAA), and the card then follows that cable, without the length in its name (`lenGone` keeps the old length). In the cable picker it is one row with the cable's current lengths; a wire on the card in an older drawing shows and prices the cheapest current length until another is picked. The report lists these cards under *Length no longer sold, cable still sold*.

**Plugs: male/female and mono/stereo** (RCA, minijack, jack 6.35/4.4/2.5 mm, XLR; since 2026-11-23). Worked out by rules, nothing to enter per product:

- **Device ports** (`P.plug` in `js/ports.js`): sockets are female (F), XLR outputs male (M). A port carries two channels (an RCA pair, a TRS jack) unless what it carries is mono (sub, coaxial, digital, video, trigger, AES, mic) or its label names one channel (…L, …R, LFE, MONO). A port can be set by hand in the Editor (the plug field beside the connector: *2× F auto*, *1× F mono*, *2× M stereo*…), stored as `g` and `ch` on the port, e.g. for a product with a fixed cable ending in plugs.
- **Cables** (`derivePlugs` in `tools/cable-ends.js`, by the hourly build): genders written in the name (*Y-Split 2M 1F*, *(1F/2M)*, *DIN Female*), else the website's cable type (subwoofer, coaxial, digital and AES/EBU cables mono; signal and minijack cables stereo), male at both ends unless the name says otherwise. Stored on the product as `eg` (genders) and `ech` (channels) per end, `plugsAuto` when worked out; set by hand in the Editor beside End A / End B (*Stereo · M*, *Mono · F*…) (then kept in `data/own.js`).
- **A connection is as mono as its mono side:** SUB OUT (one RCA) into a subwoofer's stereo LINE IN takes a mono sub cable without a warning.
- **Warnings, never blocking** (`P.plugIssues`): both female (a cable with plugs or an adapter is needed), both male, a mono cable on a stereo connection (only one channel gets through), a stereo cable on a mono connection (a plug left over). The cable picker lists the cables whose plugs fit first and shows the problem under the others; plugs are shown as chips, *[RCA ×2 | M]*: M (male, a plug) solid, F (female, a socket) outlined (`Pn.plugChip`); the header shows the ports' plugs (*[RCA ×1 | F] → [RCA ×2 | F]*). A wire whose cable does not fit gets ⚠ on its label (not printed), with the reason in its tooltip. Relaterede produkter suggests a cable whose plugs fit and shows the warning on the row if the chosen one does not.
- **To check:** `build/plugs.md`, written by each build: the cables that could not be decided (guessed stereo male–male), the device ports decided on weak grounds (a minijack that could be a headphone output or a trigger), and the ports of adapters and wireless boxes, which often have a fixed cable with plugs. First run: 67 cables from the website's type, 26 from the name, 10 guessed; 23 ports and 8 adapter ports to check.

Wiring two ports whose connectors do not normally go together (e.g. HDMI to RCA) shows a warning; common pairs joined by one cable (Minijack–RCA, Jack–RCA, DIN–RCA, USB-A–USB-B, Toslink–Mini-Toslink, RCA–XLR…) do not. When a card is replaced, connections are carried over by: same key → same signal and number → same signal → same connector type. `tools/io-migration-report.md` lists how each of the 409 old labels was renamed.

## Usage statistics

`js/stats.js` sends usage statistics to **Umami** (cloud.umami.is, free Hobby plan, cookieless, no consent banner needed) with the website id in `data/config.js` (`analytics: { umami: "717c1877-…" }`, the site danielchmc.github.io in Umami; empty = off). Only from the live site (danielchmc.github.io / hifiplanner.dk over https), never from a local copy, and not from browsers that ask not to be tracked.

- **Pages:** the planner counts as `/planner`, the customer view as `/kunde`. The drawing in a link (after `#`) is never sent. Umami's *Realtime* view shows who is on each right now.
- **Who uses it:** sellers are told that their activity is recorded with their name, only to find out how the program can be improved (and that customers are not recorded by name): on the login screen, in Settings, and once in an *Om statistik* dialog after login for sellers who were already logged in. Once a seller has seen it (logged in from the login screen, or pressed *Forstået*; kept in `statsAck` in that browser), the visit is identified in Umami by the seller's name, never the seller number (`umami.identify`, so *Sessions* and *Realtime* show who it is) and planner events carry `saelger` (the name). Until then, and always on the customer page, only the shop.
- **Events,** each with the shop number (planner; plus the seller's name, see above) or the shop's name (customer view), never anything about the customer: *Login*, *Print* (with or without cover, related products on or off), *Ordrelinjer (CSV)*, *Kundelink kopieret*, *Katalog åbnet*, *System tilføjet*, *Relaterede produkter åbnet* / *tilføjet* (how many cables and accessories), *Kundeside åbnet* (with how many related products were shown), and on the customer page one event per kind of click, so Umami's Events view counts them apart: *Kunde: relateret produkt* (with the product's name and SKU), *Kunde: produkt i tilbuddet* (with the product), *Kunde: ring*, *Kunde: mail*. Click rate of the related products = *Kunde: relateret produkt* ÷ *Kundeside åbnet*; which products, under the event's properties.
- **More events** (2026-11-23): *Aktiv* every 5 minutes while the planner is the visible tab and the seller has used mouse or keyboard in those 5 minutes (true usage time per shop and seller; planner only); *Print* carries the proposal's value (`vaerdi`, kr incl. VAT, from the price list), `produkter` (cards), `system` and `plantegning` (ja/nej); *Kundeside åbnet* carries `kilde` (*QR-kode*, *PDF-link* or *Link*: the printed QR code links with `#q=`, the clickable link beside it in the PDF with `?pdf#t=`, a copied link with `#t=`, the same page; the `?pdf` also keeps Chrome/Edge from dropping the link from the PDF, which they do for a link to the printed page itself with only a different `#…`) and `tilbud`, a short fingerprint of the link, so the same proposal opened again counts on the same value (nothing in it identifies the customer); *Ny sælger oprettet* (the name); *Fejl* (message and file:line of an error in the planner or on the customer page, at most 5 different per visit).
- **KPIs in Umami:** Goals on *Kunde: relateret produkt*, *Kunde: ring*, *Kunde: mail*, *Print*, *Kundelink kopieret*; Funnel *Kundeside åbnet* → *Kunde: relateret produkt* (click rate on related products); Event properties for breakdowns (*shop*, *saelger*, *kilde*, *produkt*, *vaerdi*); Retention for whether sellers come back; all collected on a Board.
- **Statistik** (admin, top bar): shows Umami's read-only share page inside the planner. Umami Cloud's free plan has no API, so it uses the website's share URL (Umami → Websites → Edit → Share URL, with Realtime and Events ticked), pasted once and kept in that browser only (anyone with the link can read the statistics, so it is not in the repository). If Umami refuses to be shown inside another page, the frame stays empty; *Åbn i ny fane* opens the same page.
- Add an event elsewhere with `HP.stat('Name', { extra: 'value' })`; it is queued until Umami has loaded and never throws.
- `index.html` also still loads Google Analytics (G-BW00S9FNRZ, the old planner's property), which sets cookies.

## Item number (SKU) and the right-click menu

- **Item number:** selecting one product card shows its SKU first on the selection bar; clicking it copies it. The right-click menu has "Kopiér varenr." with the SKU beside it. A card with a colour chosen gives that colour's own SKU (`C.skuOf`).
- **Right-click menu:** on a selection it is short — for a product: Udskift, Farve / finish, Relaterede produkter (accent), Kopiér varenr., Dublér, Slet — and **Flere…** reopens it at the same spot with everything (Vend, Se billedet nærmere, Kopiér, Tæl med i prislisten, Placér forrest/bagerst, Redigér produkt, Gem som genvej, and the canvas items). Right-clicking empty canvas shows the canvas items as before.
